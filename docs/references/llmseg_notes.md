## 1. 方法

**整体：** 冻结的 MLLM 是唯一的视觉组件。每次调用都是无状态的，不用工具，只返回 JSON 坐标；其余步骤都是确定性代码，包括解析、限框、光栅化、组合、清理和停止判断（§3）。

**阶段 1，检测（1 次调用）：**
- 输入图与查询，输出每个实例的框、置信度和形态描述（morphology）。拓扑描述（连通分量数、洞数）可选，主配置关闭。
- IoU ≥ 0.9 的近重复框合并。论文写按阅读顺序保留，最多 N_max=200 个；代码注释写的是按置信度保留（`pipeline.py`）。

**阶段 2，B 样条分割（1 次批量调用，覆盖所有实例）：**
- 每个实例给出闭合周期均匀 B 样条的控制点，16–64 个。
- 次数 d∈{1,3} 由模型自己选，同一次调用里所有实例共用一个次数（§3.2，附录 F）。
- 采样数 m=min{2000, max{64, round(2(w+h))}}，偶奇填充成 mask（附录 B.2）。

**框约束：**
- 采样后的曲线点被逐坐标夹到实例框内，所以 mask 不可能越出检测框。
- 因此检测质量是分割质量的上界（§3.2）。
- 提示里还把框写成显式的数值不等式（附录 B.1）。

**阶段 3，带符号的局部修正（每轮至多 2 次调用）：**
- 第一次调用：给模型看当前 mask 的叠加图，让它提出带符号的 focus box（+ 表示补，− 表示删）。每个实例每轮最多 6 个框，且必须落在该实例的框内。
- effect gate 去掉几乎改不动 mask 的框；全部被去掉时跳过本轮的重描调用。
- 第二次调用：批量重描剩下的框，固定三次样条，每框 4–12 个控制点（§3.3，附录 F）。
- 同一轮内先做删除再做补充，然后桥接邻近的孤岛，并做形态学开闭、去斑点和去假洞（附录 B.2）。

**软锁定（soft lock）：**
- 每个实例带一个带符号的承诺场 Λ（公式 4，α=1）。像素未承诺时直接写入；与已有承诺同向时加强承诺；反向时先消耗承诺，消耗完才翻转像素。
- 作用是抑制振荡（附录 B.2）。
- 附录 B.3 的单例（图 7）：第 3 轮的提议在空承诺场下会补 7,791 像素，在已有承诺场下只改了 1 像素。

**提前停止：**
- 规则：|M^(t) △ M^(t−1)| < ε·|∪ 实例框|，ε=0.005，连续 s=3 轮成立就停。
- 分母用框的并集，不用整图（§4.1）。
- ε 和 s 是在 16 张开发图上定的，这些图不属于任何评测集，随代码发布（附录 E.1）。

**主配置：** 三个阶段都用 Gemini-3.7-Flash，T=8，N_max=200，拓扑关闭，所有基准用同一组设置、不按数据集调参（§4.1，附录 C.2）。

## 3. 消融（附录 E.3 表 10、表 11，§5.3 表 4，图 6、15，附录 E.4）

**读法：**
- ReasonSeg val 200 条，每个配置跑 3 次取均值 ± 标准差；RefCOCO val 200 条，每个配置跑 1 次。都是 T=12。
- 基准行是"报告配置"（拓扑关闭）：ReasonSeg 70.7±0.74 gIoU、74.7±1.62 cIoU、14.6 次调用；RefCOCO 79.3 gIoU、79.8 cIoU、17.5 次调用。
- 下表中缩进的变体是在"拓扑开启"行上改动的，与拓扑开启行比较。拓扑开启行：ReasonSeg 69.2±1.34 / 72.6±0.23 / 14.3；RefCOCO 76.7 / 77.3 / 16.8。
- 同一配置重复运行，gIoU 波动 0.1–1.3；cIoU 的标准差最高到 4.6。作者自己说这些结果"只看方向"。

## 4. 局限与失败模式

**作者自述（附录 E.7、E.8，§6）：**
- 继承后端的失败：歧义提示上的幻觉检测，坐标格式不稳定（附录 B 的修复能缓解但不能消除）。
- 单次调用要几秒到几分钟，视频和实时应用不在范围内。
- 细长或分形结构是样条的弱项，例如视网膜血管。
- 无定形的背景类：Cityscapes 上 mIoU 比 SAM 3 低 10.4。
- 关节体的深窄凹陷：闭合曲线切不进去，例如手。
- 由于框约束，质量受检测框上界限制。
- API 模型会更新，复现性受限。作者固定了版本并发布全部记录。
- 像素级边界松：IoU 阈值 0.90 处 mask AP 只有 16.4，SAM 3 在 LVIS 上为 42.5、COCO 上为 24.3（附录 E.5）。
- SA-Co/Gold 的存在判断弱：cgF1 低 9.0，但 pmF1 持平。
- ReasonSeg 上 SAM 3 Agent"更好也更便宜"：72.4 对 69.4 gIoU，11 s 对 153 s，$8.3 对 $15.6 每千图（附录 E.6）。

**我看到的问题：**
1. **RefCOCO val 的两组数字对不上。** 500 条子集、T=8 时，LLMSeg 是 71.6 gIoU / 71.2 cIoU（表 7）；200 条消融集、T=12 时是 79.3 / 79.8（表 11）。相差约 8 个点，而论文又说 T 从 8 到 12 只改变 < 0.1 gIoU。200 条是怎么取的，论文没有交代。这说明子集之间的方差很大，或者取样方式不同。
2. **ReasonSeg val 的 cIoU 随运行波动大。** 不同运行分别是 71.5（表 1）、74.7±1.62（表 10）和 72.6（图 6、15）。主表是单次运行，不带置信区间；RefCOCO 也只跑了一次。
3. **正文说法与表格不一致。** §5.3 称"让模型选次数有帮助"，但表 10、11 在整体上并不支持（见第 3 节）。图 20 的图注写"Gemini 3.7 Flash 是达到 72.9 终版 gIoU 的最便宜后端"，而表 9 中 Gemini 3.7 Flash 是 69.4，72.9 是 GPT-6 Astra。§5.3 有一句话断在"After refinement,"，HTML 与 PDF 都是如此。附录 D.4 称表格"用的是 T=12 的运行"，与主配置 T=8 矛盾。
4. **"完整划分"并不完整。** RF-100VL 实际是每个子集取前 20 条，见代码的 `reproduce_paper.sh`，合计 1,987 条。
5. **开源模型都经 OpenRouter 调用**，精度、量化和服务方都不可控。Gemma 4 26B 的中位耗时是 2,151 s/图。这些数字不能直接当作"本地部署某个开源模型"的能力。
6. **比较口径混用。** 表 1 把 500 条子集上的结果与已发表的全划分结果放在一起排粗体和下划线。

## 5. 代码（github.com/ajhamdi/llmseg-code @ `f2191e66`）

**基本信息：**
- 公开，**MIT 许可**。仓库创建于 2026-10-12，该 commit 时间为 2026-10-22。
- Python ≥ 3.10。依赖只有 numpy、pillow、scipy、scikit-image 和各提供方的 SDK：**没有 torch，也没有任何学习型 CV 模型**。
- 发布了 16 张开发用的 toy 图，以及离线测试 `tests/test_offline.py`（覆盖路由、坐标、指标和一次脚本化的完整管线运行）。

**提供方：**
- 支持 Gemini API、Anthropic、OpenAI、OpenRouter 四家，按模型名路由：
  - 名字含 `/` 的走 OpenRouter；
  - `gemini*`、`gemma*` 走 Gemini API；
  - `claude*` 走 Anthropic；
  - `gpt*`、`o<数字>` 走 OpenAI；
  - 其他默认走 OpenRouter。
- 可以用 `--provider` 强制指定。
- **没有本地或开源模型的接口。** OpenRouter 的 base URL 写死在代码里；OpenAI 客户端构造时没有传 base_url。按 openai SDK 的常规行为，它会读环境变量 `OPENAI_BASE_URL`，所以也许能指向本地 vLLM 的 OpenAI 兼容服务，但我没有验证，代码也没有声明支持。

**与我们接 Qwen3.5-9B 直接相关的实现细节（`llm.py`）：**
- **坐标约定按模型名判断。** 名字的最后一段以 `qwen` 开头就按 0–1000 网格、x 在前；Gemini/Gemma 用 0–1000 网格、`box_2d=[ymin,xmin,ymax,xmax]`；其他模型用像素。
- **换算有一个隐患。** `_needs_grid_rescale` 的判断是：所有值都 ≤ 1000 就当成网格坐标去换算。COCO 图像宽高 ≤ 640，如果模型其实回答的是像素，会被**静默地错误缩放**。务必确认 Qwen3.5 的原生约定，以及我们 E1 协议用的坐标系。
- 不设置任何采样参数，用提供方默认值。只有 Anthropic 设了 `MAX_OUTPUT_TOKENS=32000`；OpenAI 兼容的调用不传 max_tokens。
- 每次调用超时 400 s，重试 5 次。失败按空 mask 计分。

**评测：**
- `evals/` 覆盖 ReasonSeg、RefCOCO/+/g、SA-Co/Gold、LVIS、COCO、ADE20K、Cityscapes、ODinW13、RF-100VL，另有一个通用的 COCO json 脚本。
- 同时报告阶段 2（`seg_*`）和终版（`rec_*`）的指标。`compare_subset.py` 在共同条目上做配对比较。每条有断点续跑，支持 `--dry-run`。
- RefCOCO 数据来自 HF 的 `jxu124/refcoco{,plus,g}`，图像是 COCO train2014。每个（句子，目标）对是一条，用 `random.Random(0)` 打乱后取 500 条。GT 为空且预测也为空时记 IoU=1。
- `reproduce_paper.sh` 固定 T=8 和论文的条目选择。

## 6. 对我们定位的影响

**1. 开源 26–27B 并不好，SAM 3 Agent 仍明显领先。**
- ReasonSeg val 上，Gemma 4 26B 和 Qwen3.8 27B 的终版 gIoU 是 56.1 和 51.0，比 Gemini-3.7-Flash（69.4）低 13–18。
- 它们比单独的 SAM 3（13.1）高 38–43，但 SAM 3 本来就不会解析推理式查询，这个比较没有多大意义。
- 有意义的参照是 SAM 3 Agent：Gemma 4 31B 驱动 SAM 3 能拿到 73.1，而同一个 Gemma 4 31B 自己画样条只有 56.2，差 −16.9。
- 换句话说，在开源后端上，"让 LLM 从现成的 mask 里挑"远强于"让 LLM 自己画"。这与我们 W2-c 的思路（LLM 从不含学习的候选里挑）方向一致，区别是我们的候选来自 GrabCut 等，不来自 SAM。
- 在 RefCOCO 系列上，**只有 Gemini 的数字**：我们的 5 个 test 划分上均值 cIoU 71.8（不修正 66.1），**高于 W2-c 的约 0.64**。审稿人很可能拿它来对比，我们需要把比较框定在"同一个开源小模型"的范围内。

**2. 对 9B 零样本的预期（推测，论文没有 <26B 的数据）：**
- **锚点：** 与我们同代的旗舰 Qwen3.5 397B 在 ReasonSeg 上只有 50.2 / 49.5，修正为负收益；Qwen3.8 27B 是 51.0。同代内规模几乎不起作用，但跨家族的弱模型可以掉到 14–25，例如 Qwen3-VL-235B 有 49% 的条目回复失败。
- **推测的结果：** 9B 关思考、贪心解码时，RefCOCO 系列的成绩大概率明显低于 Gemini 的约 72 cIoU，**很可能低于 W2-c 的 0.64，也可能低于 W1-F 单候选的 0.58**。理由有两个：LLMSeg 的 mask 上界是它自己的检测框；在同样的框里，9B 要用坐标画出比 GrabCut 更贴边的轮廓，难度很大。
- **修正环：** 预计修正对 9B 是中性或负收益。
- **建议的报告方式：**
  - 按 CLAUDE.md 的多轮记账规则，同时报阶段 2（2 次调用）和终版（≤ 18 次调用），附调用数、token 和墙钟；
  - 另报格式失败率与截断率；
  - 300 句的子集要带 CI。论文自己在 RefCOCO 的不同子集之间就差了约 8 个点。
- **GPU 时估算的参照：** RefCOCO val 每图 17.5 次调用，开源后端在 ReasonSeg 上 12.3–21.8 次。乘以 1,500 句，约 2–3.3 万次调用（我算的）；每次输入约 1.9k token（含图像），输出至少几百 token，坐标多时会更长。

**3. 定位：**
- LLMSeg 是与我们"不用学习型 CV 专家"最接近的先例，在某种意义上更纯：最终几何由 LLM 写出，之后只有确定性代码。
- 我们的差异点应强调三条：
  - 开源小模型，能力长在自己的权重里，并且经过训练；它是零样本前沿 API。
  - 计算量：它每图 13–18 次调用、约 150 s；我们的计算量要按同样的口径记账后对比。
  - 论文自己的证据：弱后端不会自我修正（11/21 个后端修正为负收益），能力完全取决于后端。这正好支持"需要训练"的论点。

**4. 值得借鉴的设计：**
- **框约束**（mask ⊆ 框）：零成本的安全不变量，与 W2-c 用 E1 框一致。任何由 LLM 输出的几何都应套上这条。它能提升阶段 2 的结果，非连通目标上 +11.3 cIoU。
- **带符号的局部修正 + 软锁定 + 提前停止**：可以作为训练后多轮协议的候选。按我们的规则，要在看 test 之前固定 ε、s、T，并做匹配计算量的对比。作者用 16 张开发图定 ε、s 的做法值得照搬。零样本弱模型做不了修正，但修正本身可以成为一个训练目标，写进 T 通道的文本输出。软锁定没有消融，只能当工程细节，不能当证据。
- **B 样条：** 整体精度没有优于多边形，好处是坐标少 1.7 倍、大目标更好。如果我们让 LLM 输出轮廓，或在 E3b 的 ≤ 300 个新 token 预算里输出轮廓，它可以作为省 token 的参数化方式，但不要期待精度提升。
- **先描述再画：** 没有可测的收益，不必采用。
- **工程细节：**
  - 按模型的原生坐标约定提问，在代码里换算；
  - 用框检测控制点是否被转置；
  - 批量回复截断时保留已完成的实例；
  - 空 GT 计分，失败计 0；
  - 在共同条目上做配对比较；
  - "低图像细节"会损失 3.5–4.5 gIoU，要检查我们适配器的输入分辨率。

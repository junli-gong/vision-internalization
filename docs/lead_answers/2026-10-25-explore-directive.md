## 二、关于 LLMSeg

### 1. 它是什么（根据项目主页，全文请你读后核实）

- **来源**：KAUST 的 Abdullah Hamdi，2026-10-21 上传，arXiv 2610.29409；项目主页 abdullahamdi.com/llmseg。
- **定位**：不训练，冻结的多模态 LLM 是唯一的视觉部件，不加分割头，也不加 mask 解码器。模型只输出坐标（框和 B 样条控制点，JSON 格式）；解析、限制在框内、光栅化、停止判断，全部由确定性代码完成。
- **三个阶段**：
  1. **检测**：输出实例框，每个框附一句形状描述，按阅读顺序，去掉近似重复的框。
  2. **分割**：一次调用，为每个实例返回闭合的周期 B 样条外轮廓，可选地加洞；控制点被限制在框内，采样后填充成 mask。
  3. **修正**：把当前 mask 的叠加图交还给模型，模型提出带符号的局部框（加或减），一次批量调用重新描这些局部的样条；最多 T 轮，mask 不再变化就提前停止。
- **三个关键设计**：
  - **框约束**：控制点和采样点都限制在实例框内。
  - **软锁定的合成**：每个实例带一个有符号的"承诺"场，后面的修正轮次不能简单地推翻前面的结果。
  - **成本有上限**：T = 8 时，每张图最多 18 次调用。
- **结果**：
  - 用 Gemini-3.7-Flash 时，在相同样本上和 SAM 3 相当或更好；在 LVIS、COCO、ADE20K、ODinW13、RF-100VL 上领先，SAM 3 只在 Cityscapes 上领先；ReasonSeg val 上 cIoU 71.5。
  - 后端对比共 21 个，其中包括 Gemma 4 26B、Qwen3.8 27B 两个开源模型，在 200 条 ReasonSeg val 上报 gIoU。

### 2. 请你先做的事（1 天内，不占 GPU）

1. **读全文**，写一页摘要放进 `docs/references/llmseg_notes.md`，重点写：

   - 局限，以及每张图的实际调用次数和 token 数；
   - 代码仓库是否公开、许可证是什么。
2. **判断对我们定位的影响**：如果开源后端在 26–27B 上已经很好，在摘要里明确写出来，并立即告诉负责人。

### 3. 作为外部基线

- 许可证允许的话，用它的官方代码，配 Qwen3.5-9B 零样本，跑和 W2-c 相同的 test 子集（5 个划分各 300 句）；4B 如果便宜也跑。
- 指标：除了我们的 cIoU，也报告 gIoU，方便和它的后端图对照。
- 跑 test 之前把它写进预注册，作为外部基线。计算量照常记账。
- 如果它在 9B 上不低于 W2-c，立即报告负责人，论文的定位需要重新讨论。
- 它用 Gemini 的数字，只在论文里引用为参考，我们不跑闭源模型。

### 4. 可以借鉴的思路

1. **几何的手**：用 B 样条代替多边形或网格，输出短、平滑、闭合，还能表示洞。
2. **先说后画**：先用一句话描述形状，再动手描线。
3. **局部、带符号的修正**：只在出错的局部框里加或减，而不是整体重画。W1 失败在"修改把好的结果改坏"，这正是它要解决的问题。
4. **软锁定**：后面的轮次不能推翻前面已确认的结果。
5. **框约束和提前停止**：限制错误的范围，也限制成本。

### 5. 论文里的定位

LLMSeg 证明了：足够强的模型，配上合适的几何输出和修正回路，不训练就能分割。我们的位置是它没有回答的问题：

- 为什么开源小模型做不到（E1、E2：信息在中间层，说不出来）；
- 为什么不该让 LLM 直接输出像素（E3：稠密输出和语言互相争抢，干扰随规模缩小）；
- 怎样用训练让小模型做到，同时把语言代价控制住（W2-c，以及下面探索出来的方法）。

论文里描述 W1 的失败时，要限定为"在我们这种回路设计和 9B 模型下"，不写成"LLM 的自我修正是噪声"这种一般性结论。

## 三、自主探索的授权

### 1. 目标

为"以 LLM 为内核完成高层 CV 任务"这个想法，找到最好的可行方法。以 RefCOCO 系列的指代分割为主任务，定位和计数作为语言护栏同时报告。

一个好的方法同时满足三条：

- 分割质量高；
- 能力来自 LLM 自身，用"换模型、换工具"的消融可以证明；
- 语言代价小。

### 2. 不需要请示，可以自主做的

- 设计、实现、比较新的方法：提示词、工具、回路、输出表示（B 样条、多边形、带符号的局部框等）、候选生成器。
- 训练：LoRA 的 SFT 或 RL，监督只能来自真值（例如从真值 mask 拟合出的 B 样条、真值算出的最优候选），可以加回放、调步数、秩和缩放等。
- 在探索用的数据上自由地反复试验、调参、做消融（见第 4 条的数据划分）。
- 在探索预算之内自行安排 GPU，不逐个报批。

### 3. 必须先请示负责人的

- 动用任何 test 划分，或者密封的 devcheck3（见第四节）；
- 修改任何已经预注册的判据；
- 超出探索预算；
- 使用许可不明的新数据；
- 改动主线已冻结的协议或权重；
- 任何会写进论文的结论。

### 4. 硬边界（不得违反）

- **工具边界与 W1、W2 相同**：只允许不含学习的工具；禁止 SAM、检测器、深度模型、CLIP、DINO、OCR 等任何学习型视觉模型或预训练权重，以及 OpenCV 的 DNN 模块。
- **只用开源模型**：不调用任何闭源 API。
- **单一权重**：评测时不按任务切换适配器。
- **监督只来自真值**：不得用任何模型（包括更大的 LLM）生成的标注来训练。唯一的例外是基座模型对自己的自蒸馏回放。
- **计算量照常记账**：多轮方法照硬约束第 11 条，记录 token 数、调用次数和墙钟时间。
- **数据划分**：
  - 可以用于探索：RefCOCO 系列的 train 划分；W1 用过的 800 句；devcheck2（已经用于 W2 的判定，之后只能当开发集，不能再用来做判定）；以及从 val 里另取的探索用句子。
  - 第四节的 devcheck3 必须先密封，在判定之前不得查看任何系统在上面的结果。
  - test 划分在判定通过之前一律不碰。
- **铁律照旧**：两个 Slurm 任务不停。

### 5. 预算

- **探索预算**：120 GPU 小时。
- **主线优先**：RUN-0072、RUN-0073、N44 的 (b)(c)、LLMSeg 基线都发出去之后，探索才使用空出来的 GPU。

## 四、从探索到论文：唯一的通道

探索出来的方法要进入论文的主结果，只有一条路：

1. **现在就密封 devcheck3**：从 RefCOCO 系列的 val 里取 500 句，与 W1、W2 用过的句子都不重叠，按哈希固定，写入预注册。在判定之前，任何人不得查看任何系统在上面的结果。
2. **最多选 2 个候选**进入判定，每个候选在判定前写好预注册：方法、冻结的参数、预测。
3. **判定**（97.5% 置信区间，配对 bootstrap），候选满足以下任一条即通过：
   - cIoU 显著高于 W2-c，即差值的 CI 下界 > 0；
   - cIoU 不劣于 W2-c（差值的 CI 下界 > −0.02），**并且**健康检查没有任何一项标红。

   第二条的意思是，同样的分割质量下，语言代价更小，也是一个更好的方法。
4. **通过之后**：跑和 W2-c 相同的 test 子集，进入论文；W2-c 照样报告，不撤下。
5. **没通过**：探索结果在论文里只作为附录或"未来工作"描述，明确标为探索性。

**时间**：

- 10-26 → 11-01：探索；
- 11-02：devcheck3 判定，最多 2 个候选；
- 11-03 → 11-04：通过的候选跑 test；
- 11-05：实验冻结。

赶不上的，留到下一轮继续，不压缩判定流程。

## 五、探索方向参考（不限于此，由你判断）

1. **LLMSeg 式的几何回路，零样本**：B 样条加框约束、带符号的局部修正、软锁定、提前停止，直接用 Qwen3.5-9B。它和外部基线的区别在于，我们可以按自己的协议做消融。
2. **训练"描 B 样条"**：从真值 mask 拟合 B 样条控制点作为文本目标，LoRA SFT。之后可以用 IoU 作奖励做 RL。注意 E3 的经验：C3 在 0.8B 上学多边形文本效果很差，所以先在 4B、9B 上试。
3. **W2-c 加局部修正**：在挑出的候选上，再做 LLMSeg 式的带符号局部修正和软锁定，看能否逼近"最优候选"的上限。
4. **更好的候选池**：把 LLM 自己描的 B 样条也作为候选，和贴边算法的候选放在一起挑。先看"最优候选"的上限能提高多少，再决定值不值得做。
5. **先说后画**：让模型先描述形状，再给框或曲线；比较有无这一步的差别。
6. **控制语言代价的训练配方**：回放比例、步数、LoRA 的秩和缩放、KL 锚定，画出"分割质量对语言代价"的折中曲线。
7. **RL**：在工作台里用 IoU 作奖励，对挑选或修正的决策做 GRPO，可以先在 2B、4B 上试。

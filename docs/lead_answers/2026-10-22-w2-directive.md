## 〇、方向

- **W1 的放弃只针对 W1 这一个方法**：9B 开源模型零样本使用工具，并让它反复修改结果。"以 LLM 为内核、用工具完成 CV 任务"这个整体想法继续推进。
- **新开 W2**：新的方法、新的预注册、新的判定数据。W1 的失败照实写进论文。
- **这个阶段不与前沿闭源模型比较**：W2 只用开源模型，比较对象见第二节第 6 条。
- **这一轮是否投 CVPR**：由第三节的去留规则决定。

W1 的数据给出了 W2 的设计原则：

| 设置（开发-检查集 500 句，9B） | cIoU |
|---|---:|
| 模型自己的框 | 0.507 |
| 自己的框直接交给 GrabCut（W1-F） | 0.576 |
| 完整工作台，LLM 反复修改（W1-1） | 0.470 |

LLM 的语义定位是好的，贴边算法能在框的基础上继续提升；坏在让 LLM 看着叠加图逐步修改，它的修改基本是噪声。工具调用还拖累了定位和计数。

**所以 W2 的原则是：LLM 只做它擅长的事——判断是哪个物体、在候选里挑一个；逐像素的拟合全部交给工具，不让 LLM 动手修改。**

## 二、W2 任务书

### 1. 主张

冻结或只用文本监督微调的开源 LLM，借助只含仪器的工具，在指代分割上超过"有工具、但没有 LLM 参与决策"的固定流程（W1-F）；能力属于 LLM 的语义判断和选择；语言能力不受损害。

### 2. 工具的边界

与 W1 相同：

- 允许：不含学习的眼、手、贴边、核对工具，以及 Python 沙箱；
- 禁止：任何学习型视觉模型或预训练权重，以及 OpenCV 的 DNN 模块。

### 3. W2-a：候选加挑选（主方法，不训练）

**流程**：

1. **提出**：LLM 用原生格式给出框；可选地，再给出少量前景点和背景点。这一步沿用 E1 的定位协议。
2. **生成候选**：工具在框和点的基础上，生成固定数量 K 个候选 mask（K 在开发集上定，建议 6–8 个），例如：
   - 默认参数的 GrabCut（等同 W1-F 的输出，作为 1 号候选）；
   - 不同参数或不同初始化的 GrabCut；
   - 两种尺度的 SLIC 超像素，在框内合并；
   - 以点为标记的分水岭；
   - 框本身。
3. **挑选**：把候选编号后并排叠加在原图上，交给 LLM，只让它回答一个编号，或者回答"都不对"。回答"都不对"时，提交 1 号候选，也就是 W1-F 的结果。

**约束**：

- 只有提出和挑选两轮，不做任何修改轮。每轮思考最多 2048 个 token，到上限强制收尾。
- 按输出类型路由，不按任务路由：要求输出 mask 的任务走上面的流程；要求输出框或数字的任务（定位、计数）直接按 E1 协议单轮作答，不调用工具。这样修正了 W1 拖累定位和计数的问题。
- 计算量照常记账：token 数、工具调用次数、墙钟时间。

### 4. W2-c：训练 LLM 做挑选（次要方法，训练，时间允许时做）

- **数据**：在 RefCOCO 系列的 train 划分上，用 W2-a 同一个候选生成器生成候选，用真值 mask 算出 IoU 最高的那个候选，作为挑选的标签。这是由真值得到的监督，不涉及任何学习型模型。
- **训练**：在 4B 或 9B 上用 LoRA 做监督微调，目标是"提出的框"和"挑选的编号"，全部是文本输出。
- **依据**：E3 的经验是，文本监督（C3）没有伤害语言，还有提升。W2-c 只训练文本形式的决策，预计不会遇到 E3 那种稠密输出与语言的冲突。
- **要求**：W2-c 训练出的模型必须做健康检查（简报 8.11），并报告定位和计数的 T 文本读数，证明语言没有受损。
- 训练数据与评测数据按图像去重，规则照旧。

### 5. 模型

- 开源的 Qwen3.5-2B、4B、9B。判定用 9B。
- 27B 仍为可选，只在两张卡都空闲时跑。
- 不使用任何闭源 API 模型。

### 6. 数据与对照

**数据**：

- **调参**：W1 用过的 800 句（300 句调参集加 500 句检查集），可以随意使用。
- **新的开发-检查集**：从 RefCOCO 的 val 里，再取 500 句与 W1 不重叠的句子，**只用于第三节的判定**，判定之前不得查看任何系统在上面的结果。
- **主结果**：test 划分，每个划分 1,000 句的固定子集，判定通过之后才能运行。

**对照（全部在同一模型、同一协议下跑）**：

| 编号 | 设置 | 说明什么 |
|---|---|---|
| 自己的框 | E1 协议的框，直接光栅化 | 起点 |
| W1-F | 自己的框交给默认 GrabCut | 有工具、没有 LLM 决策 |
| 随机挑选 | 在同一组候选里随机选一个 | LLM 的挑选是否好于随机 |
| 最优候选 | 用真值挑 IoU 最高的候选 | 候选池的上限，挑选能力的天花板 |
| W2-a | 候选加挑选（零样本） | 主方法 |
| W2-c | 训练过的挑选 | 次要方法 |
| W2-S | 同一个 W2-a，换 2B、4B、9B | 能力是否随 LLM 变强 |
| 参照 | E1 零样本多边形、E3b（2B，训练过）、LISA-7B、专家 SOTA（灰色参考线） | 定位在哪条赛道 |

"最优候选"和"随机挑选"两条线最重要：W2-a 落在它们之间的位置，直接量出 LLM 挑选的价值。

**判定**：主配置的 cIoU 显著高于 W1-F。因为有两个主配置，按多重比较校正，用配对 bootstrap 的 **97.5%** 置信区间，下界 > 0 才算通过。

**判定时间**：

- W2-a：约 10 月 29 日；
- W2-c：最晚 11 月 1 日。

**结果**：

- 至少一个主配置通过：进入 test 主实验，按三段式投 CVPR，第三段为通过的那个 W2 方法；
- 两个都不通过：这一轮不再尝试新方法，不投 CVPR。

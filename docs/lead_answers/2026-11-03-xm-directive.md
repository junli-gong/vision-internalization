# 项目负责人指令（2026-11-03，用户转交；原文照录）：把 X-2 扩展为同时做检测和实例分割的一个 LLM（X-M）

## 〇、目的与原则
- 论文标题拟定为 *Your LLM Is Also a Computer Vision Model—No Specialist Decoder Needed*。用一个模型补齐目标检测（给一个类别，框出图中所有实例）与实例分割（给一个类别，为每个实例描出轮廓）的证据，对标 Rex-Omni（CVPR 2026）与 SAM 3。
- 原则：1. X-2 的全部结果冻结，不做任何改动，论文核心照旧以 X-2 为准，X-M 是扩展。2. X-M 和 X-2 用同一套做法：LLM 先给框，再描 B 样条轮廓（16 个控制点）；不含学习的工具负责贴边（GrabCut 三元图）；单一 LoRA，监督只来自真值，加基座的自蒸馏回放；不用任何学习型视觉模型。3. 有退路：X-M 没有通过第五节的判定，论文就只用 X-2，X-M 不进正文。4. 只用开源模型，不比前沿闭源模型。

## 一、批准事项
- 新开 X-M 这条线。预算 100 GPU 小时；预算之内的单个运行不再逐个报批，在日志里记下预估和实际用量；超出再报。优先级：X-M 排在所有其他运行之前。动用新的评测数据（COCO 2017 val、LVIS val、ReasonSeg val）的请示一并批准，但必须按第二节的划分和第五节的流程使用。

## 二、数据与划分
- 训练数据：COCO 2017 train 的检测和实例分割标注（从真值 mask 拟合 B 样条控制点作为文本目标，做法与 X-2 相同）；X-2 原有的 RefCOCO 系列训练数据；基座的自蒸馏回放，比例与 X-2 相同。
- 去重（最要紧，开训前必须完成并写进报告）：COCO train2017 里凡是出现在 RefCOCO 系列任何评测划分（val、testA、testB、test，以及 devcheck2、devcheck3 和 test 子集）中的图像，一律从训练数据中剔除。同样剔除 ReasonSeg val 的图像，以及第五节判定集与最终报告集里的所有图像。去重清单与哈希写入预注册。
- 评测划分：调参 = COCO val2017 中 300 张（只用于调提示词与推理设置）；判定（密封）= COCO val2017 中另取 500 张，与调参集不重叠，只用于第五节的判定，判定前不得查看任何系统在上面的结果；最终报告 = COCO val2017 中再取 1,000 张，与前两份都不重叠，判定通过后才能运行；描述性报告 = LVIS v1 val 子集（1,000 张）、ReasonSeg val，判定通过后运行，只作描述；不劣于 X-2 的检查 = X-2 用过的 2,300 句开发数据（判定用；RefCOCO 的 test 子集只在最终报告时再用一次）。
- 评测单位是"图像 × 该图中出现的类别"，每对都要求输出该类别的全部实例。crowd 标注按 COCO 惯例排除。

## 三、方法
- 推理协议（每个"图像 × 类别"调用模型 2 次）：1. 列出实例：给图像和类别名，模型按阅读顺序输出该类别所有实例的框，最多 30 个。2. 描轮廓：在同一次调用里，为每个框输出一条 16 个控制点的 B 样条。
- 确定性的后处理（不含学习）：对框做 NMS 去掉近似重复；控制点限制在各自的框内；光栅化，作为 GrabCut 三元图的种子，逐个实例贴边。指代分割仍按 X-2 原协议，换成 X-M 的权重。
- 训练：从基座开始，用全部混合数据训练单一 LoRA，配方与 X-2 相同，只多出 COCO 的两类数据，1 个种子。先测吞吐；如果 9B 在第六节的时间内训不完，在预注册里写明后改用以下两种退路之一并在报告中说明：从 X-2 的检查点继续训练；改在 4B 上做，以 4B 的 X-2 作为不劣于检查的参照。

## 四、对照与指标
- 对照（全部用同一模型尺寸、同一协议）：基座零样本（E1 协议）——检测的起点；基座零样本的框交给 GrabCut——实例分割的起点；X-M 自己的框交给 GrabCut、不描样条——能力归属；X-M 的框换成框内椭圆再交给 GrabCut——与 X-2 相同的椭圆消融；X-2（指代分割与语言）——不劣于检查的参照；Rex-Omni（外部参照，仅检测）——先核对许可证，允许的话在同样的数据上跑；SAM 3、LLMSeg、Grounding DINO——引用文献数字作灰色参考线，不跑。
- 指标（LLM 不输出置信度，统一用基于匹配的 F1，与 Rex-Omni 一致）：检测 = IoU 0.5 下的 F1，另报匹配上的平均 IoU；实例分割 = mask IoU 0.5 下的 F1，另报匹配上的平均 mask IoU；指代分割 = cIoU（RefCOCO）、gIoU 与 cIoU（ReasonSeg）；语言 = 大题量 MMLU-Pro（2,000 题）与 IFEval（541 条）、CountBench 计数、定位，口径与四方表相同。

## 五、去留规则（写于任何 X-M 训练与评测之前，不得修改）
在密封的判定集（500 张）和 2,300 句开发数据上，以下四条必须全部满足（配对 bootstrap，95% 置信区间）：
1. 描轮廓仍然关键：实例分割 F1，X-M 显著高于"X-M 的框直接交给 GrabCut"，即差值的 CI 下界 > 0。
2. 成为检测器：检测 F1，X-M 显著高于基座零样本，即差值的 CI 下界 > 0。
3. 指代分割不退步：在 2,300 句开发数据上，X-M 的 cIoU 不劣于 X-2，即差值的 CI 下界 > −0.02。
4. 语言不明显变差：大题量的 MMLU-Pro 和 IFEval，X-M 相对 X-2（同尺寸、种子 0）的差值，CI 下界都要 > −2 个百分点。
结果：全部满足——跑最终报告集、LVIS 子集、ReasonSeg，以及 RefCOCO 的 test 子集，进入论文，写成"同一个 LLM 完成检测、实例分割和指代分割"。任何一条不满足——X-M 不进正文，只在附录里作为探索性结果如实描述；论文按 X-2 定稿。

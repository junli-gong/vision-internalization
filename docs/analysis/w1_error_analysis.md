# W1 的错误分析与对 W2 的含义（D113-4；管理员，2026-10-22）

- 数据：RUN-0063，开发-检查集 500 句，9B，W1-1，冻结的协议 D111。重放与分类的代码见 D114（`src/w1/replay.py`），运行是 RUN-0064。
- 原始报告：`experiments/W1/0064_w1_error_analysis/error_analysis.md`；逐条的数据在 `replay.jsonl` 与 `error_analysis.json`。
- 重放：500 句全部重放。5 句不一致，不进分类，都出在 `run_python` 上（见第 4 节）。进入分析的 495 句，返回图的 sha256 全部一致。

## 1. 四类的占比

先后为：没有提交 → 修改把好的结果改坏 → 种子点放错 → 贴边算法本身的问题。每条样本只归一类。

| 类 | F1：最终 IoU < 0.5（258 句，占 52%） | F2：比 W1-F 差 0.05 以上（235 句，占 47%） |
|---|---:|---:|
| 没有提交 | 70（27%） | 50（21%） |
| 修改把好的结果改坏（过程中最好的 mask 比最终的高 ≥ 0.10） | 8（3%） | 7（3%） |
| 种子点放错（写进工具的种子框与真值框的 IoU < 0.5） | 96（37%） | 72（31%） |
| 贴边算法本身的问题（种子对，工具没做出好的 mask） | 84（33%） | 106（45%） |

## 2. 主要发现

1. **"修改把好的结果改坏"很少**，只占 3%。
   - 若每条都交过程中最好的那个 mask，cIoU 也只从 0.471 升到 0.485；W1-F 是 0.578。
   - 所以 W1 输给 W1-F，主要不是因为"LLM 的修改是噪声"，而在后面三条。
2. **种子框比模型自己的原生框差得多。** 这是最大的系统性问题。看种子框与自己的框都有的 451 句：

   | 量 | 种子框（写进工具的） | 自己的框（E1 单轮，原生格式） |
   |---|---:|---:|
   | 与真值框 IoU 的中位 | 0.698 | 0.936 |
   | Acc@0.5 | 72.5% | 93.1% |

   - 逐条差的中位是 −0.171，种子框更差的有 397 句。
   - 同一个模型，在多轮回路里开着思考"估"坐标再写进工具，远不如它单轮、关思考、用原生格式直接给的框。
3. **没有提交**占失败的 21–27%。这 70 句上，即使交过程中最好的 mask，cIoU 也只有 0.142，W1-F 是 0.548。多数是根本没做出像样的 mask：其中 38 句从头到尾没有种子。
4. **贴边算法本身的问题**：种子对了（种子框 IoU 中位 0.70–0.74），GrabCut 等工具仍没做出好的 mask。按 F2 口径这是最大的一类，占 45%；这些句子上 W1-F 的中位 IoU 是 0.77，说明换个起点或参数，工具是能做好的。
5. **各工具的作用**：
   - `refine` 133 次，有升有降，中位变化为 0；
   - `select_superpixels` 中位 +0.18，但写出后的 IoU 中位只有 0.38；
   - `draw_box`、`draw_polygon`、`draw_points` 中位都为负。

## 3. 对 W2 设计的含义

- **种子用原生框，不让模型在回路里写坐标**：W2-a 的"提出"一步用 E1 协议的框，与"自己的框"同一次生成，这一条直接修正了最大的系统性问题。
- **没有"不提交"**：W2-a 永远有候选可交，"都不对"或解析失败时交 1 号，即 W1-F。
- **候选池要覆盖"贴边的问题"**：同一个好种子上，GrabCut 的参数、初始化，以及 SLIC 的合并方式，结果差别很大。候选的多样性用来补贴边的失败，挑选的价值也主要在这里。
- **修改轮去掉的收益不大**，但也没有坏处，符合 D113 的原则。
- **对预测的提醒**：W2-a 对 W1-F 的增益，只能来自"在同一个原生框上挑出比默认 GrabCut 更好的候选"。W1-F 已经用了原生框，所以第 2 条的好处 W1-F 也有。增益完全取决于候选池的上限与挑选的准确率。这与 W2 预注册第 7 节的预测一致，不改预测。

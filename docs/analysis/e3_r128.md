## 3. 管理员的读法（建议，待负责人确认）

- 按规则照实写："L_r128 = 4.7，满足事先写下的'容量不够'条件"。
- 同一段紧接着写明两点：
  1. 秩 128 让 C3 与 E3b+C3 都大幅退化（8 项平均分别掉 18.2 与 12.0 点），计数与检测两臂都为 0；
  2. 去掉这两项后，L 只从 8.2 降到 6.3。
- 结论：**这个变体区分不了"容量不够"与"输出端冲突"。** 论文不据此主张干扰来自容量。
- 像素干扰（P_seg、P_depth）按 D99-1 只作描述，不下结论。种子 2 的网格结果 10-22 01:30Z 推到 GitHub 后补算：
  - P_seg_r128 = 0.100 / 0.054 / −0.215，平均 −0.020；
  - P_depth_r128 = 0.013 / 0.141 / −0.163，平均 −0.003。
  - 种子 2 的 E3b+C3（r128）指代分割 cIoU 反而远高于 E3b（r32）的同种子读数，所以 P 为负。
  - 0.8B 的网格读数受地板效应影响、种子间波动很大，这里只照录。

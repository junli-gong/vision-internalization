## 任务

### 1. 落地脚本（`scripts/data/`）

每个数据源一个子命令，例如 `python scripts/data/land_e1.py <源> --root $PROJ/data`。

**共同要求**
- **可断点续传、幂等**：已落地且哈希相符的文件跳过。
- **清单**：每个源写一份 `MANIFEST.json`，内容包括：来源 URL 与 revision 或 commit、每个文件的 sha256 与字节数、许可原文、落地时间、脚本的 git commit。
- **大压缩包**：解到 `TMPDIR`，服务器上是内存盘（`/dev/shm` 下的项目目录）；只把需要的部分留在 `--root`，然后删掉压缩包。
- **磁盘**：开跑前估算体积，超过 `--budget-gb` 就拒绝（默认 10 GB，给结果留余量）。每一步记 `df`。
- **网络**：不用浏览器式的并发轰炸，并发 ≤ 8；失败重试带退避；不可达的 URL 记录下来，不静默跳过。

**要落地的源**（体积与来源见 data_sources；数字仅供核对）

1. **RefCOCO / RefCOCO+ / RefCOCOg**：
   - 内容：refs pickle 与所需的标注（mask 的来源见 A §1.6）。
   - 来源：官方主机已不可用。按 data_sources A §1.1 与 A §1.7 选一个**内容与官方 pickle 一致**的来源，逐字节或逐条核对，并写进清单。
   - 评测划分：RefCOCO 与 RefCOCO+ 取 unc 的 val、testA、testB；RefCOCOg 取 umd 的 val、test。
   - 只下载这些评测划分用到的 COCO train2014 图像，按单图 URL 下载（A §1.5）。
   - 训练划分在 E1 不需要，不下载。
2. **COCO val2017 检测子集**：
   - 500 张，用固定种子抽取，先剔除 D20 的探针用图；
   - 下载 `instances_val2017.json` 里这 500 张的标注：压缩包解到 TMPDIR，只留子集标注；
   - 图像按单图 URL 下载。
3. **ODinW13 子集**：
   - 13 个数据集，各取 GLIP 测试配置所用的划分（data_sources 已记），每个数据集用固定种子抽 ≤ 50 张；
   - 只留子集与标注；
   - 许可按数据集逐个写进清单。
4. **CountBench**：HF `nielsr/countbench` 打包版，491 张有图。按 D11 的约定使用。
5. **NYUv2**：
   - 来源：官方 labeled `.mat`。如果 `$ROOT/datasets/nyuv2` 里已有 sha256 与官方一致的文件，只读使用，不复制、不修改，那是别的项目的目录；否则下载到 TMPDIR。
   - 抽出 Eigen 654 张测试图（`splits.mat`，1-based）的 RGB 与深度（米）到 `--root`，压缩存储。
   - 写明 Eigen crop 的两种写法（data_sources §3），我们用哪一种。
6. **BLINK Relative_Depth**：只用 val（124）。
7. **CV-Bench**（test 2,638）与 **EmbSpatial-Bench**（test 3,640）：从 HF 落地。
   - 图像与题目按原样保存；
   - 去重相关的事实（与 COCO val2017、ADE20K、NYUv2 的重合）写进清单。

### 2. 开发子集（D11-6）

- 只有测试划分的基准（CV-Bench、EmbSpatial-Bench、BLINK val、CountBench），各用固定种子切一个开发子集：50 条或 10%，取较小者。
- 开发子集只用于解析器、提示格式的开发与批处理一致性验收（D28-5），从报告的数字里剔除，报告写明剩余的 n。
- 有训练划分的数据集，开发子集从 val 里取：RefCOCO 系列取 val 的 200 句；NYUv2 取 Eigen test 以外的官方 train 图。规则写明。
- 开发子集的 id 清单入库：`configs/e1_dev_subsets.json`。它是协议的一部分。

### 3. NYUv2 相对深度点对（E1 的 T 文本任务）

- 由 GT 构造，固定种子。默认值如下，最终以 E1 预注册为准：
  - 每张图 5 对；
  - 两点都在 Eigen crop 内且深度有效；
  - 像素距离 ≥ 图像短边的 10%；
  - 深度相对差 ≥ 15%，以排除含糊的对；
  - "A 更近"与"B 更近"各半。
- 渲染：在图上画带标签 A、B 的点标记，用执行器白名单里的叠加渲染。颜色与大小固定，写进常量。
- 点对清单入库：`configs/e1_nyu_pairs.json`。图像不入库。

### 4. 统一的样本加载器（`src/data/`）

- 每个任务一个加载器，返回统一的记录：`id`、图像路径（一张或多张）、任务字段（指代表达、类别列表、选项、点坐标等）、GT（框为绝对像素 xyxy，mask 为多边形或 RLE，计数，选项字母，近的那个点）、来源与划分。
- 剔除 D20 的图像与开发子集；每个加载器写明剔除了多少。
- 去重检查（D11）：做成函数，加载时就核对。被剔除的样本写进统计，不静默丢弃。
- 不做模型相关的事。提示的拼法属于 E1 评测框架（下一个任务）。

### 5. 测试

- 加载器：用 `tests/fixtures/e1/` 下的小 fixture（每个源几条，图像用合成的小图）。
- 落地脚本：
  - 断点续传与幂等，用本地的假 HTTP 或文件 URL 模拟；
  - 清单与哈希；
  - 预算拒绝。
- 开发子集与点对：固定种子下逐字节复现；点对满足全部约束；A/B 各半。
- 在开发机上对每个源做一次真实的小样本落地（每个源 ≤ 10 条），确认解析与 schema 正确。
  - 放在 scratchpad，不入库；
  - 结果写进总结；
  - 大文件一律不在开发机下载，例如 NYUv2 的 `.mat`，用它在 data_sources 里的 schema 与 range read 验证即可。

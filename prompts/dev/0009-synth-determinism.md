[DEV-TASK 0009] E5 生成器跨机器逐位复现的修复（生成器版本 1 → 2）

## 背景

RUN-0006 在服务器（x86_64 Linux）上核对了 DEV-0007 钉住的 10 个样本摘要：8 个相同，2 个不同。见 `reports/0006-env-synth.md` 与 `experiments/P0/0006_env_synth/synth_digests.json`。

管理员在开发机（arm64 macOS）上用同一探针脚本算了各分量的子摘要，与服务器逐项对照：
- **`occlusion/test/2`**：
  - 相同的有：`meta.scene`、目标 mask、目标网格、凸包基线。场景规格完全相同。
  - 不同的有：图像、`object_masks`、可见部分基线、难度、基线 IoU。
  - 结论：另一个物体的光栅化结果在两台机器上不同。
- **`physics/test/2`**：
  - `meta.scene`、`meta.final_poses`、`meta.difficulty`、`meta.baseline_iou` 与全部 mask 都相同；
  - 只有顶层 `meta` 不同，是某个没量化的浮点量（多半来自 pymunk 的速度或穿透量）。
- **排除项**：服务器上关掉 numpy 的 SIMD 分派，摘要不变。

嫌疑按可能性排序：
1. 光栅化走 pycocotools（`src.executors.raster.polygons_to_mask`）。它是编译过的 C 代码，arm64 的编译器可能把 `a*b+c` 融合成 FMA，x86_64 不会，所以边界像素可能不同。
2. 超越函数：`math.cos/sin/atan2` 走平台 libm，`np.cos/np.sin` 在 NEON 与 AVX 上是不同的实现，末位可能不同。量化能挡住绝大多数差异，但挡不住跨越量化边界的情况。
3. `np.mean` 等聚合的求和顺序可能随 SIMD 宽度变化；由此算出的难度值会影响分档。
4. pymunk（Chipmunk，C）的浮点末位可能随平台不同：
   - 量化后的位姿这次相同；
   - 没量化的派生量不同；
   - 用没量化的量做拒绝判定，可能在边界上翻转。

## 目标

- **c 与 e**：在任何平台上逐位相同。它们不依赖物理引擎，没有理由做不到。
- **d**：
  - 物理引擎的浮点行为不在我们控制之内。规范平台定为服务器（x86_64 Linux，固定的 pymunk 版本），d 的数据只在规范平台上生成（D24）。
  - 但生成器里我们自己写的部分必须确定：光栅化、三角函数、量化、判定、写进元数据的值。这样跨平台的差异只可能来自 pymunk 本身。

## 任务（只改 `src/synth/` 与它的测试）

1. **精确的整数光栅化**：
   - 在 `src/synth/` 里自写光栅化，不再调用 pycocotools。顶点已量化到 1/256 px，乘以 256 后是精确整数。
   - 按像素中心做点在多边形内的判定，全部用 int64 整数运算，结果精确。
   - 奇偶规则或非零规则，择一写明。只在包围盒窗口里算。
   - 规则写进 docstring，并测试以下几点：
     - 与 pycocotools 在随机多边形上的差异只出现在边界像素；报告差异像素占比；
     - 正方形、三角形等构造例子的像素数精确；
     - 结果与平台无关：纯整数运算，不存在浮点路径。
2. **确定的三角函数**：
   - 数据路径上的 cos/sin/atan2 全部换成确定的实现，与平台 libm 和 numpy 无关。
   - 建议用 Python 的 `decimal`，精度 ≥ 30 位，做级数与参数约简，再量化到现有的量化步长。
   - 单位形状的顶点表也可以一次算好存进仓库，由脚本可复现。
   - 速度要满足下面第 6 条。
3. **确定的聚合**：
   - 影响分档、拒绝或写进元数据的求和与均值，改用 `math.fsum`，它的结果是精确舍入的；
   - 或者改为整数计数。
4. **元数据与判定只用量化后的值**：
   - pymunk 给出的速度、穿透量等，先量化，再用于拒绝判定和写进元数据；
   - 不写入任何没量化的浮点量；
   - 摘要覆盖的每个字段都必须由确定的计算得出。
5. **生成器版本改为 2，并重新钉住摘要**：
   - 新建 `tests/data/synth_digests_v2.json`：c、e 每个划分各 20 个序号的摘要（共 120 个）；d 同样取 60 个。
   - 测试规则：
     - c、e 在任何平台上都必须全部相同；
     - d 的清单只在规范平台（`platform.machine()=="x86_64"` 且 Linux）上比对，其他平台跳过并写明原因（D24）；
     - 开发机上另做一条 d 的同机确定性测试：两次生成相同。
   - d 在规范平台上的摘要由管理员在下一个 RUN 之后填入，属于常量级修改。在那之前 d 的清单可以先放开发机的值，并在文件里标注"待服务器填入"。
6. **速度**：c ≥ 50 样本/秒（单核），e 与 d 不低于现在的一半。报告前后对比。
7. 更新 `tests/test_synth_repro.py` 的文档字符串，写明新的核对规则与失败时的处理。

## 0. 一页结论

- **建议通过 G2。判断：信息基本在隐藏状态里，瓶颈主要在输出通道。按简报 §8.3，E3b 与 E4 的优先级上调。**
- 依据：
  1. **稠密信息在第 0 层就有，进 LLM 之后在前 1/4 到 1/3 的层里还略有增强。** 线性探针在 L7–L8 上比第 0 层好：
     - 深度 AbsRel 好 6–20%；
     - 法向平均角误差低 1.2–2.9°；
     - 语义分割在 4B、9B 上 mIoU 高 2.4–4.0 个点。

     四个尺寸都一样，CI 不重叠。
  2. **指令能调制图像 token。** 指令在前时，指代分割在第 0 层接近"不知道指的是谁"（线性 cIoU 约 0.20）；到 50–56% 深度的层，线性升到 0.25–0.32，两层卷积升到 0.36–0.49。
  3. **最后一层丢掉一部分。** 语义分割与法向在最后一层比第 0 层还差，线性探针 8/8 格 CI 不重叠；深度大致回到第 0 层附近（±1–8%）；指代分割保留了一部分增益。
  4. **增益不是光栅位置带来的。** 每个光栅四分位都有增益，包括最早的 q1，它看到的前文最少（D53-3）。
  5. 把这些和 E1 放在一起：同一批模型能框出物体（71–90%），隐藏状态里也读得出深度、法向、分割与指代，但写不出轮廓。多边形与网格接近 0；格式强制之后，网格也只剩全 0 或全 1（RUN-0030）。
- **对 E3 的含义**：
  - E3b 的输出读的是最后一层，而最后一层恰好丢了一部分稠密信息，所以 E3b 的稠密监督要把信息带到输出端。
  - E3a 的逐层混合可以直接读中间层。
  - 这正是 E3a 与 E3b 对比要回答的问题："哪个通道更好"。
- **需要你决定的事**，详见 §7：
  1. 确认 G2，确认 E3 预注册（v1，正式取值与预测已写好）；
  2. 两台机器的排期：E5 主比较的用量比原先估的多很多（2B 约 81 B200 GPU 小时，不是 10–20），需要定一个压缩办法；
  3. N28：B200 训练数据放在哪；
  4. 噪声底的口径：同配置重跑逐位相同，噪声底是 0，那条"两倍噪声底"的规则因此失去作用。

## 4. 检查结果

- **仪器**：
  - post_proj 与第 0 层逐位相同：16/16，`post_proj_check.equal = true`，最大差 0。
  - GPU 上的上采样单元测试：88 条全过，含 CUDA 用例（RUN-0029 第 1 步）。
- **噪声底**：0.8B 四个任务同配置重跑，216 个探针的标题指标**逐位相同**，差全为 0。
  - 这说明 A800 上的 E2 管线可复现：上采样已是矩阵乘，探针卷积在这些形状上也是确定的。
  - 后果：E2 预注册"小于噪声底两倍的层间差异不作解读"这条规则失去作用。实际的不确定性是评测样本的 bootstrap CI，见 §2.1 的 CI 判断。见 §7 第 4 项。
- **预跑**：0.8B 深度的收敛判定通过，L0、L12、L24 三层满足（RUN-0029）。
- **可信度**：
  - 四个任务的评测集全量，n 与预注册一致；
  - 去重剔除清单生效：训练加载器读 RUN-0026 的清单，没有比较过的集合会报错；
  - 超参没在任何数据上调过。
- **精度设置**：探针卷积走 cuDNN，允许 TF32（`torch_backends.json`），D64-4 记录在案，所有模型同一设置。
- **用量**：29.19 小时，上限 34，估算 33.14。

## 6. 对假说的判断（简报 §8.3 的门 G2）

**判断：信息基本在隐藏状态里，瓶颈主要在输出通道。E3b 与 E4 的优先级上调。**

- **"在"**：
  - 第 0 层的线性探针就读得出深度、语义与法向；
  - 进 LLM 之后，前 1/4 到 1/3 的层还略有增强，而且不是位置效应；
  - 指令能把图像 token 调制成"指的是谁"，指代分割在中间层翻倍（卷积 0.23 → 0.36–0.49）。
- **"说不出来"**（E1）：同一批模型写不出轮廓，格式强制之后也画不出 mask（RUN-0030）。
- **两点保留**：
  1. **最后一层丢了一部分**：语义分割与法向在最后一层比 L0 还差。从最后一层直接输出的 E3b，需要稠密监督把信息带到输出端，不只是"教格式"。这是 E3b 加上 E3a 对照要回答的问题，也是 E3 要并列做 E3a 与 E3b 的理由。
  2. **绝对水平不高**：线性探针的深度 AbsRel 0.14–0.19、语义分割 mIoU 0.30–0.38。这是 token 分辨率上的冻结特征读数，不能与专家模型比，只用来比较层与层、模型与模型。
- **对 E3 预注册的直接影响**：
  - E3a 的逐层混合保持"全部层可学习加权"；E2 显示有用的层在 0.25–0.56 深度，混合权重的初始化取均匀即可，不另设先验。
  - E3b 照原设计。
  - "像素 token 通道和稠密读出哪个更好"（简报 §8.5）是主问题之一。

## 7. 下一步与需要你决定的事

1. **确认 G2，并批准 E3 预注册 v1**（`PREREGISTRATION.md` 的 E3）：
   - 正式取值：步数、批、学习率、混合与损失权重、泄漏检查判据；

2. **两台机器的排期**（v1，见 E3 预注册 §7）：
   - **E5 主比较的用量偏高很多**：2B、4 个数据量档 × 3 个起点 × 3 个种子、2 个 epoch，推算约 81 B200 GPU 小时（DEV-0037），D72-4 估的是 10–20。三个压缩办法，选一个：
     - (a) 1 个 epoch：约 48 小时；
     - (b) 64K 档只跑 1 个种子：约 45 小时；
     - (c) 两者都用：约 30 小时。

     我推荐 (b)：学习曲线的主信号在小数据量（1K、4K），预注册的预测也写在那里；64K 档是曲线的尾巴，1 个种子足够看方向。
   - 我建议的分工调整，与 D72-4 相比把 4B 与 9B 对调：
     - **A800**：0.8B 全部变体 × 3，再 4B 全部变体 × 3；
     - **B200**：评测优先；训练 2B 全部变体 × 3，E5 主比较（2B）；9B 排最后。

     理由：E5 主比较加评测已经把 B200 占满，4B 放在 B200 上会挤掉 E5。对调之后两台机器都约在 10 月 17–20 日完成。B200 的吞吐还没实测，这张表在吞吐与一致性检查之后定稿。
3. **N28**：B200 的训练数据放在内存盘。等你确认，确认后才能在 B200 上做吞吐与一致性检查。
4. **噪声底的口径**：同配置重跑逐位相同。E2 预注册"两倍噪声底"的规则因此失去作用。我建议：
   - E2 的层间比较改用评测样本的 bootstrap CI，即 §2.1 的口径，作为对 E2 预注册的事后说明；
   - E3 的"显著"本来就按简报：合并标准差的 2 倍加 bootstrap CI，3 个种子的离散度才是真正的噪声，不受影响。

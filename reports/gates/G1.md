- **建议通过 G1，附一项待定（N22）。**

## 4. 检查结果

- **批处理验收 v3**（D59-3）：8/8 通过。
  - 长输出两组（多边形、检测）δ = 0.03，其余 0.02；同配置重跑逐条不同 ≤ 0.1%（实测 1/43,200）。
  - 噪声底：短输出与字母读数组 ≤ 0.009；多边形与检测 ≤ 0.027。**多边形与检测小于 0.03 的差不作解读。**
- **可信度判据**（预注册 §8）：
  1. 验收通过：满足。
  2. 定位与计数的解析失败率 ≤ 5%：3 处超出，逐个解释如下，不改提示。
     - **Gemma-E2B 定位 79.6%、Gemma-E4B 定位 74.6%**：几乎都是拒答（"I'm sorry, but I cannot fulfill that request"），人物上更多。条件读数 0.715、0.808。
     - **InternVL-2B 计数 11.3%**：给出答案后又逐项列举，列举里出现了别的数字，解析规则判为 multiple_numbers。例："There are four outfits in the image. \n\nTo break it down:\n1. The woman on the left…"
  3. 与公开值能对上：
     - InternVL3.5 单 tile 偏低，原生 tile 子集与官方一致（2B：87.2 对 88.7；4B：92.4 对 92.5）。
     - Qwen3.5 0.8B/2B 关思考时与官方相差 ≤ 1.2；4B/9B 低 2.5–3.4，官方默认开思考。
     - 计数比官方低（9B 89.6 对 97.2），可能的原因有三：思考模式、分辨率、问句来源（我们用 CountBenchQA 人工问句）。
     - Gemma 4 没有公开数。
  4. n 与预注册一致：满足。
  5. 用量不超过估算的 120%：满足（13.95 / 18.54）。
- **平凡基线**：E1 不涉及，平凡基线是 E5 的事。
- **泄漏**：
  - E1 是零样本，我们没有训练；
  - 评测集剔除了开发子集与探针用图（D11、D20）；
  - CountBenchQA 出自 PaliGemma，Gemma 家族可能见过：Gemma 的计数反而是最差的（52–53%）。
- **坐标诊断**（D22-2）：只有 Gemma-E4B 有 3 条（0.005%）。

## 6. 对假说的判断

- **H1 的前提成立**：这些模型在 T 文本通道上"说不出"稠密结构。
  - 框好（71–90%），多边形与网格几乎为零，且不随规模改善；
  - 同一个模型能准确框出物体，却写不出它的轮廓。
  - 这是 E3 要改的差距。
- **E2 要回答**：这些稠密信息在隐藏状态里有没有。如果有，瓶颈在输出通道，E3b 与 E4 优先；如果没有，E3a 与 E3b 的稠密监督优先（简报 §8.3）。
- **不确定性的来源**：
  1. 选择题与点对的标题读数受位置偏好影响（N22），空间与深度任务的绝对水平与规模斜率都不稳；
  2. Gemma 的定位以拒答为主，它的严格读数不能当作视觉能力；
  3. 单 tile 低估了 InternVL；
  4. 思考子集还没出结果。

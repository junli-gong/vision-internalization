# 管理员 CC

职责：规划实验、写任务书、审查代码、git 提交推送、拉取并解读结果、维护 DECISIONS/EXPERIMENTS/FINDINGS。
**不写功能代码**——分工的目的是让每份代码都经过一次独立审查，而不是自己写自己查。

## 1. 写 dev 任务书

- 编号 NNNN 从 0001 递增（看 `prompts/dev/` 取下一个号）；补充用 `NNNN-addendum-K.md`。
- 模板 `assets/dev-task.template.md`。四段缺一不可：背景（指向规格/裁定小节）、任务（具体到
  文件/函数/行为）、约束（明确不许做的事）、验收（可运行的命令 + 期望结果）。
- 结尾固定句："完成后不要 commit、不要 push，向用户总结改动并说'已完成，请交给管理员检查'"。
- 一个任务书只做一件几小时内能完成的事；要求开发**把每一处偏离逐条列出待裁定**——
  这是流程里最有产出的一句话，开发 CC 会因此上报任务书自身的矛盾。
- 涉及约定（网格、索引、命名映射、预处理）时写明："从 X 模块 import 常量，禁止重述数字"。
- 在回复里用完整代码块呈现给用户；任务书较长时可只给要点 + "全文在 prompts/dev/NNNN"，
  开发 CC pull 后自行读。

## 2. 审查（用户说"开发完成"之后），逐项不跳步

- `git status` + `git diff` 全量读；新文件通读。没读完不许提交。
- 对照规格硬约束与 DECISIONS 逐条核对（冻结/不变量的 assert 在不在、约定有没有被改）。
- **独立复跑验收**：不采信开发的"全绿"，自己跑 pytest 与 import；有真实数据在本地就在真实
  数据上跑一遍管线。
- 范围检查：diff 里有没有任务书之外的改动；有则问清或要求撤掉。
- 对开发列出的每条偏离**显式裁定**（接受/退回），写进 commit message。
- 小问题（typo、路径、gitignore、按裁定改一个常量）直接修并注明；功能性问题不自己重写，
  写 follow-up 任务书。

## 3. 提交推送（共享工作区）

- **工作区与开发 CC 共享，禁止 `git add -A` / `git add .`**：开发可能正在同一目录写半成品。
  管理员提交自己的改动时**逐文件 `git add`**，commit 前 `git status` 确认没混入不属于本次的改动。
- dev 任务与管理员改动分开 commit：`[dev] NNNN: 摘要` / `[mgr] 摘要`；服务器用 `[results] NNNN: 摘要`。
- push 被拒 → `git pull --rebase` 再 push；**变基后 dev commit 的 hash 会变**，已写进任务书或
  台账的 hash 必须同步修正。
- 顶层派生文件（汇总表、图、供数 json）进 git；由管理员在每次拉取结果后重新生成并提交。

## 4. 写 run 任务书

- **输出目录必须带运行编号**（`runs/0008_full_evidence`），不得复用无编号的名字：两次运行同名目录下的
  `ckpt_final.pt` 大小可能完全相同，照字面执行会静默跑在旧模型上。
- 模板 `assets/run-task.template.md`。必含：校验的 commit hash、精确命令（含工作目录）、
  期望产出路径、回传 commit 格式、"实验代码 bug 一律停止+报告"。
- 仪器配置排最前；后跑的配置若依赖前者产出（如一致性校验读参照文件）写明顺序。
- 长任务：nohup + 状态文件 + **每个配置跑完单独 push**，管理员提前开始解读。
- 需要用户手动介入的步骤（授权、下载、认证）单列并说明原因。
- 可授权的运行时改动（如 num_workers）写明"已预授权、数值不变需有实证、改后重跑测试"。

## 5. 结果回来之后

- `git pull` → 重建顶层汇总 → 读 report 与原始 csv（自己再算一遍关键数，不只看表）。
- 更新 EXPERIMENTS.md 台账行（编号、日期、commit、一句话结论、report 链接）+ 里程碑。
  **台账编辑用带断言的替换**（`assert old in text`），静默未命中会让行悄悄丢失。
- 对照规格判据与决策表解读；解读是管理员的责任，服务器只贴数字。
- 异常（null 臂非零、一致性断言失败）先当 bug：要证据（已落盘的表 + traceback），定位后
  再决定是修仪器还是改判。
- 新裁定 → DECISIONS.md **末尾追加** D 编号（不插入中间，不改旧条；修订旧条用新条注明）。

## 6. 解读时的自我约束

- 预注册：诊断性运行发出前写下预测；结果出来后如实标注"兑现/未兑现/半兑现"。
- 区分三层：仪器结论（精确零、一致性）、效应结论（判据）、机制结论（中介变量）。
  报告里分开写，不要让机制推测污染判据判定。
- 中介变量（幅度、范数、损失曲线、逐 epoch 指标）从第一次运行就记——事后补不了。
- 跨数据集比较时核对**优化步数**而不是 epoch 数；固定 epoch 的 recipe 会把数据集规模差异
  换算成一到两个数量级的步数差异。

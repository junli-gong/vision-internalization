# 服务器 CC

你在算力服务器上，收到的 `[RUN-TASK NNNN]` 是管理员写的运行单（全文在 `prompts/server/NNNN-*.md`）。

## 纪律

- 先 `git pull`，校验 commit hash（任务书给的），对不上就停下报告，不要跑旧代码。
- **绝不修改实验逻辑代码。** 环境问题（依赖、路径、CUDA 配置）可以修，全部记进 report；
  代码 bug 则停止，把完整报错 + 已落盘证据推回，由管理员安排修复。
- 获得预授权而改动任何仓库文件（含 config）后，**必须重跑测试并记入 report**——config
  也可能被测试钉住。
- 共享机器：一切工作限定在项目专用目录；**不改任何全局文件**（`~/.ssh/config`、全局 git
  身份、共享 conda）；git 身份与 SSH key 用仓库级配置（`core.sshCommand`、deploy key）。
- 不可逆操作（删原始数据、删 zip）前独立复验派生物（从张量重算，不采信构建日志），
  校验和留档；删除动作与释放量记 report。
- 长任务 nohup/tmux + 状态文件；杀进程用 PID 文件或 /proc 遍历，不用 `ps | grep`。
- **启动脚本自己 export 环境**（`HF_HOME`、`TMPDIR`、pip `--cache-dir`），不依赖交互式 shell 的变量：
  一次漏 export 把 15 GiB 的权重重下进共享 `/root/.cache`，共享盘一度到 93%。
- **不修改正在运行的脚本** — bash 是增量读取的，改动会让运行中的进程当场从错位处继续或直接死掉；
  要改先复制成新文件。
- 磁盘/配额有硬约束时先探体积再下载；下载类长任务分阶段回报。
- 任务书指令与它自己的算术矛盾（如优先级与磁盘不可能同时满足）：按算术执行并显式上报，
  不照章熔断。

## Report（`reports/NNNN-*.md`）

- 执行的命令、每步耗时、GPU 型号/利用率/显存峰值、生成文件清单、警告与异常。
- 数字**原样贴表**（rc 汇总、逐 seed、中介变量），**不做解读**——解读是管理员的事。
  可以陈述"值得注意的事实"，标明"只陈述不解读"。
- 任何与任务书假设不符的发现（数据格式、瓶颈真因、步数账）单独一节。
- 自己造成的浪费或错误如实写（发生了什么、代价、已改的做法）。

## 回传

每个配置/阶段跑完单独 `[results] NNNN: 摘要` commit + push；report 最后随终版 push。
push 失败只记日志不中断后续，事后补推。

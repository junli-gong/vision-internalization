# 实战规则（由一次五天 pilot 的事故与发现沉淀，已去项目化）

每条格式：**规则** — 起因。

## git 与工作区
- **共享工作区禁 `git add -A`，管理员逐文件暂存** — 一次 `add -A` 把开发中的 11 个半成品文件
  扫进未审查的 commit 并推送，靠 force-push 抢救。
- **变基后同步所有引用了 hash 的文档** — dev commit 经 rebase 改了 hash，任务书里的校验值随之失效。
- **预授权改动仓库文件后必重跑测试** — 服务器按预授权改了 config 的 num_workers，把"唯一差异"
  测试打红，隔天才被发现。
- **性能键不进"唯一差异"比对** — 测试钉错不变量比没有测试更糟；性能参数（num_workers）允许差异，
  但要有"数值不变"的实证（改前后逐 epoch 损失逐位相同）。

## 约定与文档
- **约定只写一处，其余 import；配置注释里的数字用测试钉住** — 网格索引语义被复述后歧义
  （0-based vs 文件名 1-based，搞反整库平移一帧不报错）；模态名的连字符/下划线两份映射分叉，
  守卫失效重复下载。
- **裁定编号只追加不插入** — 三次把新条插到旧条前面，编号乱序需要返工。
- **台账/文档的脚本编辑必须带命中断言** — `str.replace` 静默未命中让两行台账丢失，后续编辑连锁失效。
- **heredoc 里含中文引号的 python 用三引号** — 一次 SyntaxError 让三处编辑全部没应用而 commit 照推。
- **任务书里"与 X 完全对齐"之类的定量主张先算再写** — 一次注释里的对齐声明与实际相差 155 倍。
- **任务书里的 shell 片段每行只写一个 export** — `export ROOT=/a PROJ=$ROOT/b` 这一行里 `$ROOT` 在赋值前
  就被展开成旧值（空），PROJ 变成 `/b`、HF_HOME 指到项目外的根盘；服务器 CC 实测发现。写进任务书、
  值守说明、启动脚本的环境块，一律一行一个。

## 仪器
- **null 臂必须精确为零，不是约等于零；开确定性算法后逐位比对** — 统计判据会让小泄漏以
  measurable=False 通过，与健康仪器无法区分。
- **两条独立代码路径的等价性作为免费校验** — 并行绑定 vs 门控顺序数学等价，同 seed 逐位比对。
- **逐位比对只在 RNG 流未分岔的位置成立** — 第 3 位 graft 的 RNG 消耗与 shuffle 排列不同，
  数值必然不同，那是构造性质不是泄漏；范围要显式限定。
- **断言放在证据落盘之后** — null 臂真出问题时手里要有表可回传，不只剩 traceback。
- **CSV 往返精度**：pandas `read_csv` 默认在 15 位有效数字截断；比对逐位相等时用
  `float_precision="round_trip"`，或直接比 CSV 原始字符串。
- **AdaptiveAvgPool 的 CUDA 反向在确定性模式下会抛错**，用 `mean` 替代（输出 1×1 时等价）。
- **测试路径用小型随机 backbone，不下载权重**；合成 fixture 故意 H≠W 抓轴序错误。
- **断言用的 fixture 要在被断言的量上取值互不相同** — 掩码全是居中方块 ⇒ 方形网格恒等于自己的转置，
  转置变异照样通过；同一批里两条样本的计数恒等 ⇒ "整批取第一条"的变异照样通过。
  形状非对称（H≠W）只挡住一半，**内容**与**批内**也要非对称。

## 跨机器差异（开发机绿、算力机红）
- **开发机上无法产生差异的属性，测试等于没写** — device、dtype、内存布局、对象同一性四类：在 CPU/tiny 上
  `assert x.device == "cpu"` 或把同一个对象同时塞进两处，删掉被测代码照样绿。一个项目里连续三次栽在这上面
  （张量布局末位差 1e-6、bf16 下可训练参数 dtype 不匹配、进模型的 batch 从未搬到 GPU）。
- **两条腿钉住**：① 代码里的**入口断言**——在任何算子之前比较 device/dtype/布局，抛自有异常并报出两个值，
  任何机器都会触发；② 算力机上的**一次运行时审计**——forward-pre-hook 挂满子模块，首个不符即停并报模块名。
  开发机跑不出真结论，但审计能在一次冒烟里穷尽全路径，包括崩溃点之后从未执行的代码。
- **`meta` 设备是开发机唯一能做的真检查** — 模块搬到 meta、输入留 cpu，纯 Python 的入口断言照样触发，
  而 `cpu → cpu` 的搬运是空操作、测不出任何东西。
- **配置等价性按规范化键值比，不按文本行 diff** — 两份 YAML 排序与注释不同会产生几十行噪声，
  被误读成"唯一差异"约束被破坏。

## 评测与报表
- **批量生成必须与逐样本生成逐 token 相同，把它写成测试** — 一处 `min(prompt_len)` 的整批截断让每对样本里
  长的那条从 prompt 中途开始生成，47% 的样本产不出锚点 token；报出来的"free-running 只有 teacher-forced 的一半"
  完全是工具缺陷，未受污染的样本上两者差 0.0002。差点成为论文里一条假的 train-test gap。
- **报告里的数字一律由脚本从产物读取生成，不手打** — 凭印象打了四行台账数字，三次运行里第三次犯；
  自查要覆盖每一个数字与每一个分层的存在性，不是抽样。
- **完美或方向相反的指标先当混淆查，别急着下结论** — "只喂 GT 区域"比"喂全图"低 6 点，看着像"选择性没用"，
  实则训练每步喂 179/256 格而 GT 中位数只有 9 格，全部样本都在训练分布外；干净的判据是**同预算**下比位置。
- **空集合报 null，不能与"全错"同形** — 快评样本里恰好没有正类，`mean([])` 返回 0.0，被打印成"准确率 0.000"。
- **完美的指标先当泄漏查** — 拒答准确率 6/6 = 1.000，因为 no-target 样本的指令字面就是"无"，
  任务可由字符串匹配平凡判定；该数度量的不是模型能力。
- **少数类重采样要按它的信息量定比例，不是无脑 1:1** — 23 条负例被 1:1 采样后每 epoch 各抽 45 次、
  吃掉一半算力，而它们的主损失项被跳过、任务又平凡可解。

## 实验设计
- **中介变量从第一次运行就记** — 事后补不了；正是它把两个数据集的相反结论统一成一个机制。
- **诊断前预注册预测**，事后标注兑现与否 — 预测对错各半的那次比全对的那次更有信息。
- **跨数据集匹配优化步数而非 epoch** — 固定 epoch 数把数据集规模差异换算成 8–155 倍步数差异，
  成了未被识别的主导变量。
- **控制组的"容易程度"要与处理组匹配** — 可死记的噪声控制看起来"无害"只是因为它在短预算下
  几乎没动；换个预算就翻转。
- **判据满足 ≠ 问题回答** — 效应可测（GO）与"哪种机制/哪一行决策表"是两个层次；可学性诊断
  （训练损失是否低于 ln K）先于任何 overlap/累积解读。
- **不对已知不完整的数据做试探性构建** — 一次多余的 build 吃了 10 分钟并拖慢并行任务。

## 数据获取（共享机、外部源）
- **先探体积再下载；zip 用 Range 抽取 central directory 定点取文件**，省 99% 流量。
- **公共 Drive 配额按文件计、随请求大小退化** — 探针要探真正的大文件并用 ≥256 KiB 请求；
  用户"复制到自己云端硬盘"得到的新文件配额独立，服务器可直拉，零用户带宽。
- **派生 cache 验证通过后再删原始数据**，校验和留档；删除前从张量独立复算，不采信构建日志。
- **两阶段监管**：窗口内正常轮询，到限后降频探针而非全停——配额可能任何时刻恢复。
- **无人值守脚本先用 stub 隔离验证控制流**（过期+关 / 过期+恢复 / 未过期三种场景）。
